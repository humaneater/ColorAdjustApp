# 白平衡方法大全

本文把网上能找到的白平衡（white balance / color balance）调整方式整理成一份可查的清单，
并说明每一种的原理、优缺点、常见出处，以及本工具（整体校色）是否实现、对应下拉菜单里的哪一项。

关键词速查：**白平衡 = 先估计或指定光源色度，再用色适应变换把该光源的中性色映射回参考白点**。
所有方法都可以归结为两个问题：

1. **白点从哪里来**：手动指定、参考物取样、相机元数据、还是算法自动估计；
2. **怎么把白点变中性**：对角增益（通道缩放）还是完整的 3x3 色适应矩阵。

## 2. 手动 / 创意型

### 2.1 双轴滑条（暖冷 + 绿品红）

最传统的做法：两个滑条分别控制蓝↔黄（温度轴）和绿↔品红（色调轴），直接对 RGB 通道做加减。

本工具旧版就是这样做的，着色器里是一段经验公式（`app.js` 的 `adjustColor()`）：

```
R += 温度 · k · (1 − R)      B −= 温度 · k · B
R += 白平衡 · k · (1 − R)    B += 白平衡 · k · (1 − B)    G −= 白平衡 · k · G
```

- 优点：直观、实时、不依赖任何色彩科学数据，适合微调；
- 缺点：**不是物理量**。同样的数值在不同画面上效果不同，无法和相机色温对应，
  也不能复用别人给的参数（例如「5200K、+10 色调」）。

### 2.2 色温 + 色调（开尔文 / Duv）

Adobe Lightroom / Camera Raw、darktable、RawTherapee、Capture One 默认都是这种方式：
滑条给出**色温（K）**和**色调（绿↔品红）**，程序据此算出白点，再做色适应。

- 色温滑条的语义是「我认为拍摄时的光是多少 K」。往右（K 变大）代表光源更蓝，补偿后画面更暖，
  这与 Lightroom 的滑条方向一致；
- 色调滑条的语义是「画面往哪个方向偏」。往右＝偏品红、往左＝偏绿，同样与 Lightroom 一致；
- 色温差用 **mired（微倒度，= 10⁶/K）** 衡量更符合视觉线性：从 3000K 到 3200K 的变化
  远大于 8000K 到 8200K，用 K 做等差滑条会「低色温段太灵敏、高色温段太迟钝」，
  所以很多软件内部按 mired 分布滑条；
- darktable 的文档特别指出：温度/色调滑条**只是界面层**，模块内部真正使用 RGB 通道系数，
  两者的换算关系依赖相机特性，因此把一台相机的白平衡参数搬到另一台相机通常不成立。

### 2.3 RGB 通道增益（相机倍率）

最底层、最接近 RAW 的做法：直接给 R、G、B 三个通道乘上倍率（通常以绿色归一化，G = 1.00），
也就是相机厂商在 RAW 里记录的 `AsShotNeutral` / WB 系数。

- 优点：与相机的白平衡完全同构，可以精确复现、双向换算；
- 缺点：不直观，不知道「往哪边拧」；在不同色彩空间（相机 RGB / sRGB / ProPhoto）里含义不同。

### 2.4 分通道曲线 / 色阶 / 色彩平衡

Photoshop 的「曲线」「色阶」分通道、GIMP 的 Color Levels、暗房的加色/减色放大机，
本质都是分通道增益/伽马，属于手工白平衡。它不假定光源模型，纯靠目测，
但可以在不同亮度上做不同修正（例如只修高光的偏色）。

### 2.5 胶片校色滤镜（mired 位移）

传统摄影用 CC 滤镜、80A/80B（钨丝灯片用日光片）、85A/85B（日光下用钨丝灯片）来改白平衡。
每种滤镜标称一个 mired 位移值，换算公式：

```
新色温 = 1 / (1/原色温 + 位移/10⁶)
```

这套思路至今保留在视频拍摄的 ND/CTO/CTB 滤镜和「mired shift」工具里。

## 3. 参考物型

### 3.1 灰卡 / 白卡

拍摄时把 18% 灰卡或白卡放进画面，后期用它的像素值确定光源。这是最可靠的方式，
因为中性表面的色度**就是**光源色度（忽略反射率偏差）。

变体：白平衡镜头盖、Expodisc、灰卡放在被摄体位置测光。

### 3.2 灰点拾色（点选中性区域）

灰卡的后期版本：在画面上点一下「应该是灰/白」的地方，程序算出通道增益或色适应矩阵。

- 本工具、Photoshop 的「灰点吸管」、Lightroom/ACR 的白平衡吸管、darktable 的
  「from image area（框选图像区域）」都属于这类；
- 关键假设：**点的那个像素是中性色**。点错了会得到很夸张的偏色；
- 技巧：选中等亮度、无高光溢出、无噪点的中性区域，多次取样取平均。

### 3.3 色卡（ColorChecker）+ 相机配置文件

用 24 色或 140 色色卡拍摄，软件拟合出相机 → 标准色彩空间 的映射（DCP / ICC 输入配置文件）。
它同时校正白平衡和色彩还原，是最严谨的流程，但需要额外硬件（色卡）和配套软件。

### 3.4 按数字校色（by the numbers）

不依赖取色器，而是用信息面板读数判断中性：屏幕上把已知应是中性灰的区域调到
R ≈ G ≈ B（对 sRGB 输出通常还要考虑 8 位量化与显示器的校准）。
这是印刷/商业修图的经典手法，本质仍是灰点法，只是用眼睛代替取样。

## 4. 相机 / 元数据型

### 4.1 机内自动白平衡（AWB）

相机的自动白平衡对取景画面做光源估计，再写进 EXIF（Adobe 的 `AsShotNeutral`、
DNG 的 `AsShotWhiteXY`）。不同厂商算法不同，常见的有灰度世界、白点检测、
色域约束、以及近年的神经网络估计。

### 4.2 机内预设

相机菜单里的固定选项，各自对应一组色温/色调：

| 预设 | 典型色温 | 说明 |
|------|----------|------|
| 烛光 / 日出 | 1900–2000 K | 极暖 |
| 白炽灯 / 钨丝灯 | 2856–2900 K | CIE 标准光源 A 为 2856 K |
| 影室灯 / 摄影灯 | 3200 K | 影室白炽灯 |
| 暖白荧光灯 | 3000 K | 荧光灯偏绿，需要加品红 |
| 冷白荧光灯 | 4200 K | CIE F2 为 4230 K |
| 日光 | 5200–5500 K | 日光片标准约 5500 K |
| 电子闪光灯 | 5500–6000 K | 与日光接近 |
| 阴天 | 6000 K | |
| 日光荧光灯 | 6500 K | CIE F7 为 6500 K |
| 阴影 | 7000–8000 K | 天空散射光偏蓝 |
| 蓝天 / 雪地 | 10000 K | |

CIE 标准光源的数值可作参照：A = 2856 K、D50 = 5003 K、D55 = 5503 K、D65 = 6504 K、D75 = 7504 K。

### 4.3 自定义 / 手动色温

相机上直接输入 K 值，或对着灰卡做「自定义白平衡」。它与本节 2.2 是同一件事，
只是发生在拍摄阶段。

### 4.4 白平衡包围

连续拍几张不同白平衡的照片（例如偏蓝/标准/偏暖），后期挑一张或合成。

### 4.5 as-shot 元数据

后期软件默认使用相机记录的 as-shot 白平衡作为起点。darktable 的
「camera reference」选项把白平衡设到相机参考白点（D65 / ≈6502 K），
使相机色彩空间里的纯白转成 sRGB 的纯白；「as shot」则直接采用机内设置。

**本工具的 RAW 流程已经在解码阶段使用了相机白平衡**（`libraw` 的 `useCameraWb: true`），
所以下拉菜单里的方式是叠加在 as-shot 之上的进一步调整。

### 4.6 双光源 DCP / ICC 输入配置文件

Adobe DCP 可以记录两个光源（通常 D65 与 A）下的色彩矩阵，按色温插值，
比单一矩阵更准确；ICC 输入配置文件则整体描述相机色彩空间 → 标准空间的映射。
两者都需要厂商或第三方提供的配置文件。

## 5. 自动估计型（色彩恒常性算法）

这类方法只从画面内容估计光源色度。Gijsenij、Gevers、van de Weijer 的综述
《Computational Color Constancy: Survey and Experiments》(IEEE TIP 2011)
把它们分成统计型、色域型、学习型等几大类。

### 5.1 灰度世界（Gray World）

Buchsbaum 1980 提出。假设**整幅画面的平均反射率是中性灰**，于是各通道均值之比就是光源：

```
e = (mean(R), mean(G), mean(B))
增益 = (1/e_R, 1/e_G, 1/e_B)（再按绿色归一化）
```

- 优点：极快、无参数；
- 缺点：画面被单一颜色主导时严重失效（大面积蓝天、草地、红墙），
  也因此会过度校正「本来就是单色」的题材。

### 5.2 白点 / Max-RGB / Retinex

Land 的 Retinex 白点假设：**画面中最亮的点来自全反射（白）物体**，于是用各通道最大值当光源：

```
e = (max(R), max(G), max(B))
```

- 优点：单色场景下比灰度世界稳健；
- 缺点：对单点高光、镜面反射、噪点、过曝极敏感（一个红色反光就能带偏结果）。

### 5.3 Shades of Gray（Minkowski 范数）

Finlayson & Trezzi 2004 把灰度世界和白点统一成 Minkowski 范数族：

```
e_c = ( mean( (I_c)^p ) )^(1/p)
```

- p = 1 时就是灰度世界；
- p = ∞ 时就是白点/Max-RGB；
- 论文推荐 **p = 6**：它在「单色场景」和「高光噪声」之间取得平衡，是无需训练的最强基线之一。

### 5.4 灰度边缘（Gray Edge）

van de Weijer、Gevers、Gijsenij 提出：**场景中边缘处的平均反射率差是中性的**，
于是对图像求一阶（或二阶）空间导数，用导数的均值代替像素均值：

```
e_c = mean( |∂I_c/∂x| + |∂I_c/∂y| )
```

- 优点：在单色大面积场景下明显优于灰度世界，因为平坦区域被抑制；
- 缺点：需要算梯度，对噪声和边缘阈值敏感，纹理少的画面退化。

### 5.5 色域映射 / Color by Correlation

- **色域映射（Gamut Mapping）**：对大量光源各算一遍「在该光源下可能出现的颜色集合」，
  选那个能把画面所有颜色都包含进去的光源（Forsyth 1990 的 gamut constraint，
  以及后续的 feasible set / 3D gamut 版本）；
- **Color by Correlation**：把图像色度直方图与「光源-色度」相关表做互相关，取最大者。

优点：不需要场景中存在白色；缺点：需要预先训练/构造的色域或相关表。

### 5.6 贝叶斯 / 自然图像统计

把光源估计写成后验概率最大化：`P(光源 | 图像) ∝ P(图像 | 光源) · P(光源)`。
先验来自大量自然图像的统计（例如自然图像的色度分布、光源色度分布），
代表工作是 Finlayson 等人的 Bayesian 方法与「natural image statistics」。

### 5.7 学习型（神经网络 / CNN）

用数据集（如 Gehler-Shi、NUS-8、INTEL-TAU）训练回归或分类网络，直接输出光源色度。
现代方法（CNN、注意力网络、Transformer）在该基准上误差最低，但需要模型权重和算力，
且跨传感器泛化仍然是问题。

### 5.8 物理型（双色反射模型 / 镜面高光）

利用双色反射模型：镜面反射分量携带的是**光源本身的颜色**，
因此从高光区域（或进行高光分离后）可以反解光源色度。适合有强高光的物体。

### 5.9 多光源 / 局部白平衡

上述方法都假设**单一光源**。真实场景常见混合光（窗光 + 白炽灯）。
多光源估计把画面分块估计光源并平滑成光照图，可以做局部白平衡，
但容易产生区域间的色块跳变，一般只在专业工具里出现。

## 6. 颜色科学型（色适应变换）

有了白点之后，需要把它映射回参考白（本工具的参考白是 sRGB 的 D65）。这一步由
**色适应变换（Chromatic Adaptation Transform, CAT）** 完成，做法都是 von Kries 型：
转到某个锥体响应空间 → 对三个通道分别缩放 → 转回来。

```
M = C⁻¹ · diag(dst_c / src_c) · C        d 为白点在锥体空间的三通道响应
```

不同 CAT 的区别只在锥体矩阵 `C`：

| 名称 | 说明 |
|------|------|
| XYZ Scaling | 直接在 XYZ 上缩放，也叫 **wrong von Kries**，效果通常最差 |
| von Kries / HPE | 用 Hunt-Pointer-Estevez 锥体响应 |
| **Bradford** | ICC 与 Adobe DNG 的选择，工程上最常用 |
| Sharp | 针对光谱锐化优化的锥体矩阵 |
| CMCCAT2000 | CMCCAT97 的简化版，用于色貌模型 |
| CAT02 / CAT16 | CIECAM02 / CAM16 使用的变换，也是 CIE 推荐的现代选择 |

CIE 出版过专门报告《A Review of Chromatic Adaptation Transforms》(CIE 160:2004) 比较这些变换。
CIELAB / CIELUV 也各自带一个白点适应（分别是 von Kries 型和 Judd 型平移）。

**为什么需要 3x3 而不是简单对角增益？** 因为相机的三通道并不等于人眼锥体响应。
Wikipedia 的「Color balance」条目整理了三种缩放方式（缩放监视器 RGB、缩放 XYZ、缩放相机 RGB），
并引用了 Viggiano 的结论：**在相机原生 RGB 里做白平衡比在监视器 RGB（如 sRGB）里做，
色彩恒常性误差小一倍以上**。本工具处理的是已经渲染成 sRGB 的像素，
因此属于「在监视器 RGB 里做」，这是一个已知的精度上限，文档末尾会再提一次。

## 7. 色温与色调的数学

### 7.1 色温、相关色温、Duv、mired

- **色温（CCT）**：与光源颜色最接近的黑体辐射体的温度，单位 K；
- **Duv**：光源色度在 CIE 1960 UCS 图上到普朗克轨迹的垂直距离，
  正值为轨迹上方（**偏绿**），负值为下方（**偏品红**）。
  荧光灯、LED 的色度通常不在轨迹上，必须用 CCT + Duv 两个数才能描述；
- **mired**：10⁶/K，色温差的视觉等距度量。

### 7.2 黑体轨迹与日光轨迹

- **普朗克（黑体）轨迹**：CIE 色温与 Duv 的官方定义基准；
- **CIE 日光轨迹（D 系列）**：日光的实际色度略偏绿于黑体轨迹
  （D65 相对黑体轨迹 Duv ≈ +0.003），真实日光更适合用日光轨迹描述；
- 两条轨迹在 4000 K 附近相差约 0.003 Duv。本工具在 3400–4600 K 之间做 smoothstep 过渡，
  避免色温滑条在这附近出现肉眼可见的跳变；低温段用黑体轨迹（钨丝灯、烛光），
  高温段用日光轨迹（阴天、阴影、蓝天），这与相机的预设体系一致。

### 7.3 从 (K, Duv) 到 3x3 矩阵

本工具 `white-balance.js` 的完整链条：

1. **色温 → 色度**：用 Kim 等人的三次多项式近似黑体轨迹 xy；用 CIE 日光轨迹公式近似 D 系列；
2. **Duv 偏移**：在 CIE 1960 uv 图上取轨迹法线方向（定义保证正 Duv 偏绿）平移；
3. **色度 → XYZ → 线性 sRGB**：得到光源白点 W；
4. **色适应**：`M_xyz = CAT(W → D65)`，默认 Bradford；
5. **换到线性 sRGB**：`M_rgb = XYZ→sRGB · M_xyz · sRGB→XYZ`；
6. **着色器**：先把 sRGB 值线性化，乘 `M_rgb`，再编码回 sRGB。

由构造可知 `M_rgb · W = (1, 1, 1)`：**假定的光源一定会被校成中性**，
这正是白平衡的定义，也是本工具数学测试里断言的不变量。

### 7.4 为什么要在 RAW / 线性光下做

白平衡是乘性（增益）操作，只有在**线性光**下才有物理意义。
SDR 的 sRGB 值是加了伽马的编码值，直接在 8 位 sRGB 上乘增益会：
一是把中性色校不准，二是让彩色（尤其高饱和色）的色相偏移。
因此：

- 专业软件在 RAW 线性数据上做白平衡；
- 本工具在着色器里先做 sRGB → 线性、矩阵、再线性 → sRGB（`applyWhiteBalance()`），
  RAW 路径全程 16 位线性数据。

## 8. 本工具的实现

### 8.1 下拉菜单 ↔ 方法对应

| 下拉选项 | 实现方式 | 参数 |
|----------|----------|------|
| 手动双轴（暖冷 / 绿品红） | 旧版经验公式，不走矩阵 | 色温、白平衡 |
| 色温 + 色调（开尔文） | 轨迹 + Duv + Bradford 色适应 | 色温 K（2000–12000）、色调（±100 ≈ ±0.02 Duv） |
| 场景预设 | 预设的 (K, 色调) 组合，写入上面的两个滑条 | 12 个预设 + 自定义 |
| 自动分析 | 5 种光源估计算法 + 色适应 + 强度混合 | 算法、强度 |
| 灰点拾色 | 点击像素的线性 RGB 作为光源 + 色适应 | 强度 |
| RGB 通道增益 | 对角矩阵（绿色归一化） | R/G/B 增益（0 → 1.00×，±100 → 0.25×/4×） |
| 关闭白平衡 | 不调整 | — |

所有方式都收敛到同一个 3x3 矩阵 uniform（`u_wbMatrix`），
差别只在「白点从哪里来」。自动分析还会把估计出的光源反算成
「等效色温 + 色调」显示出来，方便切到色温模式复现。

### 8.2 处理顺序

```
RAW 16 位解码（含相机 as-shot 白平衡）
  → 降噪
  → 白平衡矩阵（线性光，本文档第 7.3 节）
  → 曝光 / 亮度 / 对比度 / 色相 / 饱和度 / 自然饱和度 / 阴影
  → 预览或导出
```

自动分析用的是**原图**（未校色的预览）统计，不会因为反复调整而漂移。

### 8.3 已知局限

1. **在 sRGB 而非相机 RGB 上做白平衡**：如前所述，误差比相机原生空间大一倍以上，
   高饱和颜色尤其明显。彻底解决需要 RAW 级白平衡（相机矩阵）。
2. **单光源假设**：整幅画面共用一个矩阵，混合光源场景只能取折中。
3. **极端色温会溢出**：把 2000 K 用在日光照片上，蓝通道需要放大约 9 倍，
   会出现大面积削波（所有白平衡软件都有这个现象，只是工作空间不同）。
4. **自动分析按缩略图统计**：为了实时，分析缓冲最长边 320 像素，
   极端细小的中性区域可能被平均掉。
5. **灰点拾色取 5×5 邻域平均**：噪点会被抑制，但也可能把邻近颜色的像素混进来。
6. **未实现色卡 / DCP / 学习型方法**：它们需要色卡、配置文件或模型权重，
   不适合一个纯本机、无外部依赖的小工具。
